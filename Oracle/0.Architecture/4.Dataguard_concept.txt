2. 핵심 초기화 파라미터 (Initialization Parameters)

ALTER SYSTEM SET log_archive_config = 'dg_config=(chicago,boston)' SCOPE=both;

-- 갭(Gap) 복구용 서버 지정 (TNS Service Name 사용)
-- Primary(chicago)에서는 'boston', Standby(boston)에서는 'chicago'로 교차 세팅
ALTER SYSTEM SET fal_server = 'boston' SCOPE=both;

아카이브 전송 경로 설정 (LOG_ARCHIVE_DEST_n)
LOG_ARCHIVE_DEST_STATE_n 파라미터를 통해 사용할 경로들을 ENABLE 작업 해주어야함 
(2~31까지 사용 가능하므로 최대 구성 가능한 Standby는 30개)

-- 1. Local 아카이브 경로
ALTER SYSTEM SET log_archive_dest_1 =
  'location=use_db_recovery_file_dest
   valid_for=(all_logfiles,all_roles)
   db_unique_name=chicago' SCOPE=both;

-- 2. Replication (Standby 전송) 경로
ALTER SYSTEM SET log_archive_dest_2 =
  'service=boston
   async
   valid_for=(online_logfiles,primary_role)
   db_unique_name=boston' SCOPE=both;

Standby (boston) 설정 예시
log_archive_dest_2부터는 Primary와 반대로(Service와 Unique Name을 교차하여) 세팅합니다.


3. Redo 전송 및 응답 옵션
전송 방식 (SYNC / ASYNC)
 - SYNC: Standby에서 ACK(응답)가 올 때까지 Primary가 커밋을 대기. 데이터 보호에 유리하지만 느림.
 - ASYNC: Standby의 ACK를 기다리지 않고 즉시 커밋밋. 속도가 빠르지만 데이터 유실 가능성.

응답 타이밍 (AFFIRM / NOAFFIRM)
 - AFFIRM: Standby가 전송받은 리두를 디스크에 실제 기록해야 ACK를 반환. (SYNC 지정 시 디폴트)
 - NOAFFIRM: Standby가 리두를 메모리(SGA)에 수신하기만 하면 ACK를 반환. (ASYNC 지정 시 디폴트)

4. 데이터 보호 모드 (Protection Mode)
보호 모드를 활성화하거나 변경하려면 반드시 그에 맞게 LOG_ARCHIVE_DEST_n 파라미터가 먼저 설정되어 있어야 합니다.

-- 현재 보호 모드 확인
SELECT PROTECTION_MODE, PROTECTION_LEVEL FROM V$DATABASE;

 1.Maximum Protection (최대 보호)
  필수 옵션: SYNC + AFFIRM
  특징: 대기 서버에서 응답이 오지 않으면 Primary가 Shutdown, 최고 수준의 데이터 보호를 제공하지만 대단히 느립니다.
  변경 방법: DB 종료 후 MOUNT 상태에서 변경
  
  ALTER DATABASE SET STANDBY DATABASE TO MAXIMIZE PROTECTION;

 2. Maximum Availability (최대 가용성)
	필수 옵션: SYNC + AFFIRM 또는 SYNC + NOAFFIRM
	특징: 평소에는 동기식으로 작동하여 데이터를 보호하되, 
		네트워크 장애 시 Primary 가동을 유지하는 타협 모드입니다.
	변경 방법: DB 종료 후 MOUNT 상태에서 변경 가능

	ALTER DATABASE SET STANDBY DATABASE TO MAXIMIZE AVAILABILITY;

 3. Maximum Performance (최대 성능)
	필수 옵션: ASYNC + NOAFFIRM
	- 존나빠름 commit 바로함. / but 손실이 있을수도있음.
	- 해당 파라미터는 open상태에서 변경가능
	ALTER DATABASE SET STANDBY DATABASE TO MAXIMIZE PERFORMANCE;
