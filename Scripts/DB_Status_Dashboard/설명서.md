
# DB Status 대시보드 

Mysql / Oracle Status Dashboard

## 1. 접속

```
http://192.168.56.51:8000
```

## 2. 화면 보는 법

- 상단 **전체 / MySQL / Oracle** 버튼: 클릭하면 해당 종류의 테이블만 보이도록 필터링.
- 컬럼: `Hostname` / `IP` / `Cluster`(replication, ibc, standalone, dataguard, rac 등) / `Role`(source, replica, primary...) / `Service`(인스턴스·서비스 프로세스 상태) / `Replication`(복제·DG·RAC 상태) / `Checked At`(마지막 점검 시각).
- 배지 색상:
  - 초록(`active`, `ok`): 정상
  - 빨강(`inactive`, `error`, `unreachable`): 이상 — `unreachable`은 ssh/DB 접속 자체가 안 되는 상태(주로 대상 VM이 꺼져 있을 때).
  - 회색(`n_a`): 해당 항목이 원래 의미 없는 역할(예: router/backup/si/rman의 복제 상태).
- `Checked At`이 **빨간색(stale)**: 점검 주기(5분)의 2배(10분) 이상 갱신이 안 된 상태 — cron이나 서비스에 문제가 있다는 신호.
- 화면은 30초마다 자동 갱신(새로고침 불필요).

## 3. 구성 요소

| 구성 | 설명 |
|---|---|
| `check_mysql_status.sh`, `check_oracle_status.sh` | 크론(5분 간격)으로 실행되는 점검 스크립트. 각 대상 호스트에 ssh 접속해 서비스/복제 상태를 점검 후 `lab_dashboard.checks`에 기록. |
| `lab_dashboard` (MySQL, Manager 로컬) | 점검 대상 목록(`hosts`, `oracle_hosts`)과 점검 결과 이력(`checks`)을 저장하는 DB. |
| `mysql-dashboard.service` (systemd) | FastAPI 웹앱을 `:8000`에서 상시 구동. `lab_dashboard`를 읽기 전용으로 조회해 화면에 표시. |

흐름: `크론 스크립트 → lab_dashboard.checks에 INSERT → 웹앱이 SELECT해서 화면에 표시`.

## 4. 자주 하는 작업

### 웹 서비스 재시작 (코드 변경 후 등)
```bash
sudo systemctl restart mysql-dashboard
sudo systemctl status mysql-dashboard --no-pager
```

### 점검을 지금 바로 한 번 실행 (5분 기다리지 않고 즉시 갱신하고 싶을 때)
```bash
bash /storage/scripts/check_mysql_status.sh
bash /storage/scripts/check_oracle_status.sh
```

### 크론 등록 확인
```bash
crontab -l

*/5 * * * * /storage/scripts/check_mysql_status.sh >> /storage/scripts/logs/check_mysql_status.log 2>&1
*/5 * * * * /storage/scripts/check_oracle_status.sh >> /storage/scripts/logs/check_oracle_status.log 2>&1

```

### 로그 확인
```bash
tail -f /storage/scripts/logs/check_mysql_status.log
tail -f /storage/scripts/logs/check_oracle_status.log
sudo journalctl -u mysql-dashboard -f
```

### 새 MySQL 호스트 추가
```sql
INSERT INTO lab_dashboard.hosts (hostname, host_ip, db_type, cluster_type, role, service_name)
VALUES ('새호스트명', '새IP', 'mysql', 'cluster_type값', 'role값', 'mysqld' 또는 'mysqlrouter');
```


### 새 Oracle 호스트 추가
```sql
INSERT INTO lab_dashboard.oracle_hosts (hostname, host_ip, cluster_type, role, oracle_sid, db_unique_name)
VALUES ('새호스트명', '새IP', 'standalone/dataguard/rac', 'si/dg_primary/dg_standby/rac_node/rman', 'SID값', 'db_unique_name값 또는 NULL');
```

### 점검 대상에서 잠깐 제외하고 싶을 때 (삭제 대신)
```sql
UPDATE lab_dashboard.hosts SET enabled = 0 WHERE hostname = '대상호스트';
-- 또는 oracle_hosts 테이블 동일하게
```

## 6. 파일 위치 요약 (`/storage/scripts`)

```
lab_dashboard_schema.sql   # 스키마 정의 (hosts / oracle_hosts / checks / 계정)
check_mysql_status.sh      # MySQL 점검 스크립트 (크론 등록됨)
check_oracle_status.sh     # Oracle 점검 스크립트 (크론 등록됨)
setup_dashboard.sh         # 최초 1회 설치 스크립트
dash.md                    # 구축 작업 흐름/트러블슈팅 기록
설명서.md                  # 이 파일 (사용 설명서)
logs/                      # 점검 스크립트 실행 로그
webapp/                    # FastAPI 웹앱 (mysql-dashboard.service로 구동)
```
